# Proxmox Node Fleet

Five **standalone** (non-clustered) Proxmox VE 9.2.2 hosts, each fronted by its own
ProxmoxMCP-Plus instance.

## Source of truth

`proxmox-config/nodes.json` is the **only** file you edit by hand. Everything else is
generated from it:

```
proxmox-config/nodes.json          <- you edit this (gitignored, chmod 600)
        |
        +--> proxmox-config/config.<node>.json    per-node MCP config
        +--> docker-compose.yml                   one service per node
        +--> .mcp.json                            one MCP server per node
```

Never hand-edit the generated files -- `sync` overwrites them. They carry a
`GENERATED by scripts/nodes.py` header as a reminder.

## Managing the fleet

```bash
./scripts/nodes.py list      # show the fleet
./scripts/nodes.py test      # auth-check every node against its API
./scripts/nodes.py sync      # regenerate configs + compose + .mcp.json
```

**Add a node** (port is auto-assigned; the token is probe-tested before it's accepted,
so a typo'd secret fails immediately rather than at container start):

```bash
./scripts/nodes.py add --name nodeF --host 192.168.8.20 \
  --token-name nodeF --token-value 1234abcd-...
docker compose up -d
```

Use `--http-port 8820` to pin a port, or `--force` to add a node that's currently down.

**Remove a node:**

```bash
./scripts/nodes.py remove --name nodeF
docker compose up -d --remove-orphans     # deletes the container
```

Removal also deletes that node's `config.*.json`. Ports are stored per node, not
derived from list position, so **removing one node never renumbers the others** --
your bookmarks and client configs stay valid.

## Talking to one node at a time

Two independent ways, both already wired up.

**Over HTTP** -- pick the machine by port:

```bash
curl -X POST http://localhost:8813/get_node_status \
  -H 'Content-Type: application/json' -d '{"node":"pve"}'      # nodeC
```

Interactive tool browser per node: `http://localhost:8813/docs` (85 tools each).

**As MCP servers** -- `.mcp.json` registers each node separately (`proxmox-nodeA`
… `proxmox-nodeE`), so you address one node at a time by choosing its server. Each
entry attaches over stdio to that node's running container, so
`docker compose up -d` must have run first.

## Reaching the whole Proxmox API

The hand-written tools wrap ~75 of the API's 675 endpoint+method pairs. The rest is
covered by three schema-driven tools backed by the official PVE schema bundled at
`src/proxmox_mcp/data/pve_api_schema.json`:

| Tool | Does |
| ---- | ---- |
| `pve_find_endpoint` | keyword-search all 675 endpoints |
| `pve_describe_endpoint` | parameters, types, required flags, permissions |
| `pve_call` | call any endpoint, validated against the schema first |

```bash
# find it
curl -sX POST -d '{"query":"ceph osd"}' -H 'Content-Type: application/json' \
  http://localhost:8811/pve_find_endpoint

# then call it
curl -sX POST -H 'Content-Type: application/json' \
  -d '{"method":"GET","path":"nodes/pve/ceph/osd"}' \
  http://localhost:8811/pve_call
```

`pve_call` catches unknown paths, wrong HTTP verbs, missing required parameters and
unknown parameters *locally*, with a message naming the problem, rather than letting
Proxmox return an opaque 400/501. Pass `skip_validation=true` for endpoints newer
than the bundled schema.

This costs 3 tool definitions (~10.7k tokens total for all 88) instead of the
~102k tokens that 675 generated tools would need.

**Refreshing the schema** after a Proxmox upgrade:

```bash
./scripts/refresh_api_schema.py --diff-only   # show what upstream added/removed
./scripts/refresh_api_schema.py               # rewrite the bundle
docker compose up -d --build --force-recreate
```

## Two things that will bite you

**1. Every node calls itself `pve` internally.**
The names nodeA–nodeE are *ours* -- they live in filenames, container names, ports,
and MCP server names. Each host reports its own node name as `pve`. So any tool
taking a `node` argument wants `"pve"`, never `"nodeA"`. You select *which machine*
by port (or by MCP server), not by the `node` argument.

**2. These are not a cluster, so there is no cross-node view.**
`get_cluster_status` on any port describes only that one host. nodeE reports a
cluster named `Guild-A`, but it's a single-member cluster -- it does not span the
others. Aggregating all five means querying five endpoints and merging yourself.

## Operating

```bash
docker compose up -d          # start all
docker compose ps             # health
docker compose logs -f nodeC  # follow one node
docker compose restart nodeC  # restart one node
docker compose down           # stop all
```

## Secrets

Token values live in `proxmox-config/nodes.json` and the generated
`config.<node>.json` files, all mode `600` and gitignored. These are `root@pam`
tokens with full privileges: the OpenAPI ports have **no authentication**, so keep
them bound to localhost. To expose them, give `mcpo` an `--api-key` in the
Dockerfile `CMD`.
