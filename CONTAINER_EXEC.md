# Running commands inside containers

`execute_container_command` is the LXC counterpart to `execute_vm_command`.

> Cluster-wide source of truth: **[CLUSTER.md](CLUSTER.md)**. SSH specifics:
> **[CLUSTER_SSH.md](CLUSTER_SSH.md)**. Endpoint coverage:
> **[PROXMOX_API_COVERAGE.md](PROXMOX_API_COVERAGE.md)**.

## Why this isn't a plain endpoint wrapper

VMs get command execution for free: the QEMU guest agent exposes
`POST /nodes/{node}/qemu/{vmid}/agent/exec`, and `execute_vm_command` is a thin
wrapper over it.

**Containers have no equivalent.** `pct exec` is a CLI command on the Proxmox
host with no REST counterpart — there is no `/nodes/{node}/lxc/{vmid}/exec`.
Every route to a container shell therefore goes *around* the API rather than
through it. This tool implements the two that don't require installing an agent
in every container.

## The two backends

| | `ssh` | `termproxy` |
| --- | --- | --- |
| Mechanism | SSH to node, `pct exec` | console websocket, same as the web UI |
| Exit codes | real | recovered via sentinel markers |
| stdout / stderr | separate | merged (it's a PTY) |
| Needs | SSH key + node reachability | nothing beyond the API token |
| Binary output | safe | base64-framed, newline-normalised |

`backend="auto"` (the default) tries `ssh` and falls back to `termproxy` only
when the SSH *transport* fails — bad key, unreachable node, no `ssh` binary. A
command that runs and exits non-zero is a result, not a fallback trigger.

When the termproxy backend is used the result carries `"streams_merged": true`
and `fallback_reason` explains why SSH was skipped.

### How the termproxy backend recovers an exit code

A PTY gives you a byte stream, not a process result. So the command is wrapped:

```sh
__o=$( { <command> ; } 2>&1 ); __r=$?
echo "__B<nonce>__"; printf '%s' "$__o" | base64 | tr -d '\n'; echo
echo "__E<nonce>__:$__r"
```

Output is base64 so it cannot contain the markers and the terminal cannot mangle
it. The PTY echoes the input line back first — which *does* contain the literal
markers — so the parser matches on the **last** occurrence, not the first.

## Configuration

The `ssh` block in `proxmox-config/config.<cluster>.json` (generated by
`scripts/nodes.py`, so edit `proxmox-config/nodes.json` for durable changes):

```json
"ssh": {
  "enabled": true,
  "user": "root",
  "port": 22,
  "key_file": "/app/ssh/id_node",
  "connect_timeout": 10,
  "strict_host_key_checking": "accept-new",
  "hosts": {}
}
```

Node addresses are resolved from `GET /cluster/status` automatically; `hosts`
only overrides a node when you need a different route (e.g. the Tailscale
address instead of the LAN one):

```json
"hosts": { "nodeA": "100.73.229.110" }
```

Set `"enabled": false` to run termproxy-only, with no SSH key mounted anywhere.

### The key

`docker-compose.yml` mounts it read-only:

```
${PROXMOX_MCP_SSH_KEY:-$HOME/.ssh/proxmox_guild_a}:/app/ssh/id_node:ro
```

Point `PROXMOX_MCP_SSH_KEY` at a different key in `.env` if you don't want the
cluster-wide key inside this container. The key needs to reach `root@` on every
node you intend to exec into.

## Usage

```
execute_container_command(node="nodeA", vmid="910", command="systemctl is-active nginx")
```

```json
{
  "success": true,
  "output": "active\n",
  "error": "",
  "exit_code": 0,
  "backend": "ssh",
  "node": "nodeA",
  "vmid": "910",
  "fallback_reason": null
}
```

Optional: `timeout` (default 60s) and `backend` (`auto` | `ssh` | `termproxy`).

The container must be running — a stopped container raises a `ValueError`
telling you to `start_container` first, rather than hanging on a dead PTY.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| `websocket ... HTTP 401` | ticket not percent-encoded, or token lacks `VM.Console` |
| falls back on every call | key not mounted, or node unreachable on `:22` |
| `pct not available on node` | SSH landed somewhere that isn't a Proxmox host |
| output truncated | raise `timeout`; the PTY backend waits for the end marker |
